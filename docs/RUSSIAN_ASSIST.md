# Русское голосовое управление Fiendishly Good Reminders (экспериментальная ветка)

Русская локализация добавляет **русские фразы для штатного Home Assistant Assist**. Не заменяет Conversation Agent, не требует LLM и не изменяет штатные таймеры Home Assistant.

## Совместимость и границы

- Сопоставление фраз тестируется на `home-assistant-intents==2026.10.27` и `hassil==3.12.1`, как в Home Assistant Core 2026.11.2.
- Сохранены существующие английские обработчики времени и ответов; проверяются оригинальные английские тесты.
- Русские значения дат из одношаговых команд передаются в существующий планировщик FGR как нормализованные слоты. Русские ответы на *дополнительные* вопросы обрабатываются изолированным модулем `voice_ru.py`.
- Поддерживаются интенты для следующих действий: однократные и повторяющиеся напоминания, отмена по тексту/времени, пропуск, повтор, поиск, список, следующее, количество, изменение и fallback.
- Это **не универсальный разбор естественного русского языка**: неизвестные/двусмысленные фразы могут требовать уточнения. Не обещайте, что запрос принят, пока FGR не подтвердил создание.

## Напоминания через Codex Assist

Home Assistant 2026.11 добавляет инструменты FGR в **Device control (Assist)**. Оставьте включённым `prefer_local_intents` и выберите Codex Assist как разговорного агента. Чтобы дать модели доступ к нужному списку, откройте для Assist его сенсор **Next reminder**. Скройте от Assist сущность **Reminders** типа `todo`, если она была открыта. Иначе агент сохранит отдельный путь изменения этих же записей через обычные инструменты задач.

Модели доступны создание обычных и повторяющихся напоминаний, повтор последнего, поиск, список, перенос, изменение, отмена и пропуск. Для изменения и отмены инструмент требует точный ID записи. Очистка целого списка требует ответа на отдельный голосовой вопрос FGR. Без настроенного спутника запрос на очистку ничего не удаляет.

Для защиты от подмены напоминания таймером примените [патч Codex Assist](../patches/codex-assist-reminder-timers.patch) к исходникам Codex Assist v0.7.0 (`2254f71`). Сначала проверьте применимость командой `git apply --check /путь/к/codex-assist-reminder-timers.patch`. Затем примените его через `git apply` и обновите каталог `custom_components/codex_assist` в Home Assistant. Оно убирает запуск таймера из инструментов текущего хода, если доступен FGR и пользователь явно не попросил таймер. Таймеры, обработанные локально, используют штатный путь.

## Установка для проверки на HAOS

Не заменяйте рабочий FGR без резервной копии напоминаний и конфигурации: это ещё тестовая ветка.

1. В HACS → **Custom repositories** добавьте ваш форк `https://github.com/vevsvevs/fiendishly-good-reminders`. Для сборки из конкретной ветки сначала убедитесь, что HACS использует `feature/assist-ru-localization`, либо установите каталог `custom_components/fiendishly_reminders` вручную из этой ветки.
2. Создайте `/config/custom_sentences/ru/` и скопируйте туда файл `custom_sentences/ru/reminders.yaml`.
3. В `configuration.yaml` при необходимости оставьте `fiendishly_reminders:` — интеграция рекомендует это для ранней регистрации интентов.
4. Перезапустите Home Assistant Core, затем настройте хотя бы один канал доставки FGR: `assist_satellite` и/или `notify`.
5. Убедитесь, что язык голосового конвейера русский и `prefer_local_intents: true` (если используется иной LLM conversation agent).

На хосте HAOS папка `/config` контейнера Core обычно соответствует `/mnt/data/supervisor/homeassistant`.

## Как спросить о напоминаниях голосом

| Что нужно | Что сказать |
| --- | --- |
| Узнать, что запланировано | «Что у меня с напоминаниями?» · «Какие у меня напоминания?» · «Расскажи про мои напоминания» |
| Услышать список | «Озвучь мои напоминания» · «Зачитай список моих напоминаний» · «Перечисли мои напоминания» |
| Услышать ближайшее | «Озвучь ближайшее напоминание» · «Во сколько будет следующее напоминание?» |
| Спросить по названию | «Когда сработает напоминание об оплате?» · «Есть ли у меня напоминание про врача?» |
| Спросить за период | «Какие напоминания у меня на сегодня?» · «Расскажи про мои напоминания на завтра» · «Есть ли у меня напоминания на выходные?» |
| Узнать количество | «Сколько у меня напоминаний?» · «Сколько напоминаний у меня в пятницу?» |
| Спросить про другой список | «Что у Марии с напоминаниями?» · «Расскажи про напоминания Виталия» · «Какие у Марии напоминания на завтра?» |

Для поиска и подсчёта можно также назвать послезавтра, день недели, эту или следующую неделю, этот или следующий месяц. В русских запросах списка неделя начинается в понедельник. Если результатов больше пяти, Assist сообщает общее количество и озвучивает пять ближайших. При подсчёте повторяющаяся серия считается одним напоминанием.

Команды выполняет встроенный разговорный агент Home Assistant. В смешанном профиле с `prefer_local_intents: true` проверь трассу выполнения: событие `intent-end` с `processed_locally: true` подтверждает локальную обработку конкретного запроса. Если нужен профиль без перехода к LLM, выбери **Home Assistant** как разговорного агента.

## Несколько пользователей, склонение имён и адресное удаление

Список FGR выбирается не по английскому `'s`, а по **уникальному владельцу**, заданному при настройке интеграции. Для русской грамматики добавлен слот `person` и формы с `у`, `для`, `из списка`. Примеры:

| Голосовая команда | Ожидаемое действие |
| --- | --- |
| «Озвучь напоминания Виталия» | Перечень из списка Виталия |
| «Сколько напоминаний у Марии?» | Количество в списке Марии |
| «Напомни Виталию про молоко через два часа» | Создать в списке Виталия |
| «Напомни купить молоко для Марии через два часа» | Создать в списке Марии |
| «Удали напоминание про молоко у Виталия» | Удалить **одну** подходящую запись из списка Виталия |
| «Удали напоминание у Марии в девять вечера» | Поиск по времени в списке Марии |
| «Удали все напоминания у Марии» | Обязательное подтверждение очистки именно списка Марии |
| «Измени напоминание про воду у Марии» | Редактирование в списке Марии |
| «Пропусти следующее напоминание про воду у Виталия» | Пропуск одного срабатывания |

Русские падежи распространённых типов имён распознаются консервативно: `Виталий → Виталия, Виталию, Виталии`, `Мария → Марии, Марию`, `Анна → Анны, Анне, Анну`, `Сергей → Сергея, Сергею`. Это не полноценный морфологический словарь для всех редких имён и составных названий. Имена не угадываются по префиксу; совпадение должно указывать только на одного настроенного владельца.

Сервисный английский `John's` продолжает работать для английского языка, однако в русских голосовых шаблонах **суффикс `'s` не требуется**. На уточняющий вопрос о владельце также принимаются ответы «для Виталия», «у Марии», «напоминания Виталия» и простое имя. Если ответ неоднозначен, FGR переспрашивает, а не выбирает случайно.

**Одиночное удаление безопаснее прежнего:** при нескольких одинаково названных напоминаниях или двух напоминаниях на одно и то же время FGR отказывается от автоматического выбора. Уточните время или название. Для команды «Удали все» по-прежнему необходимо отдельное подтверждение через спутник.

Оговорка о синтаксисе: поскольку Hassil иногда поглощает имя в текстовом wildcard, FGR дополнительно отделяет **однозначные конструкции** вроде `«молоко у Виталия»` непосредственно в обработчике. Фразы без маркера (например, `«напомни Виталию купить хлеб»`) могут быть неоднозначны: для гарантированного выбора списка используйте `«напомни Виталию про хлеб»` или `«напомни купить хлеб для Виталия»`. Часть предложений, начинающихся с имени и заканчивающихся временем, может конфликтовать со штатным интентом таймера; предпочитайте начинать команду с `«напомни»`.

В CI проверяются русские падежи, обратное сопоставление с реальными настроенными именами, сохранение английского `'s`, одиночная отмена при двух владельцах, явный неизвестный владелец и запрет удаления нескольких совпадающих записей без уточнения.

## Безопасное массовое удаление напоминаний

Логи показали, что прежде `Удали все напоминания` не распознавалось локально, после чего Codex Assist вызвал `todo__get_items` и несколько `todo__HassListRemoveItem` **без отдельного подтверждения**. Это опасно, особенно если несколько напоминаний имеют одинаковое название: действия в журнале адресовали записи по тексту, а не по UID.

Теперь команда `Удали все напоминания` (также `Отмени все мои напоминания`, `Очисти список напоминаний`) перехватывается отдельным `CustomReminderCancelAll`. Реализация не зависит от обычной настройки `confirm_cancel` — подтверждение обязательно для **всего списка** всегда.

- На настоящем `assist_satellite` с поддержкой `ask_question`: FGR называет список и количество записей, затем ждёт явное «да». «Нет», отсутствие ответа и ошибка службы ничего не удаляют.
- В текстовом тесте Assist, где `device_id: null`, FGR **не удаляет ничего** и объясняет, что требуется голосовое подтверждение на спутнике. В частности, массовое удаление не должно переходить к Codex Assist, если сработал локальный интент.
- При нескольких списках без однозначного владельца массовое удаление запрещено: нельзя угадывать список.
- В запросах «удали все напоминания о ...» с фильтром данная команда намеренно **не** применяется, поскольку такой текст не означает «удали абсолютно все».
- Новый обработчик удаляет только снимок текущего списка, поэтому записи, добавленные после вопроса, сохраняются.

**Важно для защиты от LLM:** `prefer_local_intents: true` не блокирует неизвестные фразы. Если нужно исключить возможность удаления напоминаний через LLM даже для непривычных формулировок, ограничьте доступ агента Codex Assist к изменяющим инструментам `todo` или к сущности списка напоминаний. FGR использует собственный локальный планировщик и не нуждается в удалении через инструменты LLM.

Для обновления этой функции нужны **два файла** из одной ревизии: `custom_sentences/ru/reminders.yaml` и `custom_components/fiendishly_reminders/intents.py`. Для русского вопроса и вариантов ответа — обновлённый `voice_ru.py`. Затем перезапуск Home Assistant Core. Старый опубликованный GitHub Release автоматически не обновляется при коммитах в ветку — нужен новый тег и релиз.

## Время до глагола: локально, без LLM

В предыдущих версиях фраза `Через четыре с половиной часа напомни покормить малыша` не распознавалась локальными интентами FGR: все старые шаблоны начинались с глагола `напомни`. Поэтому `prefer_local_intents: true` не спасал — запрос уходил к Codex Assist. Начиная с этой ревизии, добавлены явные **временные префиксы перед глаголом**, а не опасный общий wildcard, который мог бы перехватывать свет или таймеры.

Поддерживаются стандартные и дробные интервалы `через/спустя N единиц`, `через N с половиной/с четвертью`, фиксированные выражения `через полчаса`, `через полтора часа`, а также время дня/даты `завтра в девять вечера напомни...`, `в понедельник напомни...` и повторения `каждый день напоминай...`. Условие сопоставления всегда требует явного глагола напоминания **после** времени.

В `tests/test_ru_hassil.py` есть регрессионные проверки обеих точных формулировок из лога, текстового слота, численных слотов и отрицательные проверки `через четыре часа включи свет` / `через полчаса поставь таймер`. На этой версии Hassil они должны распознаваться **локально**, но другие, не предусмотренные грамматикой фразы по-прежнему могут попасть в LLM. Опция `prefer_local_intents` — приоритет, а не запрет LLM.

Для применения новых временных префиксов достаточно заменить `/config/custom_sentences/ru/reminders.yaml` и вызвать `conversation.reload`. Если не ставили исправление дробных интервалов из предыдущего коммита, обновите также `intents.py` и `voice_ru.py`, после чего перезапустите Core.

## Дробные интервалы (исправление от 19 ноября 2026)

Выражения `N с половиной часа`, `N с половиной минут`, `N с четвертью часа` и `N с тремя четвертями часа` разбираются общими правилами, включая числа словами и цифрами, а также обратную форму `N часов с половиной`. Длительность передаётся как целое число, единица и слот `rel_fraction`, затем планировщик вычисляет реальную дробную величину. Например, `четыре с половиной часа` означает **270 минут**, а не 4 или 5 часов. Эти же выражения доступны при повторном напоминании и в свободном ответе на вопрос о времени.

Чтобы применить исправление, замените **оба** файла: `/config/custom_sentences/ru/reminders.yaml` и `/config/custom_components/fiendishly_reminders/intents.py`. Для продолжения диалога потребуется также новый `voice_ru.py`. После копирования из текущей ветки перезапустите Core.

## Проверка

GitHub Actions в репозитории запускает:
- `tests/test_ru_hassil.py` — локальное сопоставление фраз без выполнения действий, плюс отрицательные примеры;
- `tests/test_ru_voice.py` — русский разбор чисел и свободных уточнений времени;
- исходные английские тесты FGR — проверка отсутствия регрессий.

**Обязательно проверить в реальной HAOS до перехода в `main`:** создание/отмена/перенос из Яндекс Станции Mini, доставку `assist_satellite.announce`, повторения после перезапуска, совместимость с двумя списками и ограничение `START_CONVERSATION` для запросов подтверждения. Наличие спутника не означает поддержку продолжения диалога.


## Полное голосовое озвучивание и уточнения

FGR формирует на русском языке не только короткие ответы после распознавания фразы, но и **все собственные продолжения диалога**: вопрос «Когда напомнить?», повтор вопроса после тишины или непонятного ответа, вопрос о владельце списка, ответы «не понял», вопросы об изменении и отмене, подтверждения и отказы, результат пропуска и сообщение об отсутствии напоминаний.

Язык для синхронного ответа определяется `intent_obj.language` — языком конкретного Assist-запроса, а не языком интерфейса Home Assistant. Для отложенного напоминания этот язык записывается в поле `language` вместе с остальными данными и используется позднее для заголовков и преобразования обращений («мои документы» → «твои документы»). Новое поле **необязательное**: прежние напоминания без него остаются читаемыми и используют язык конфигурации Home Assistant.

При двух владельцах имена списков не склоняются автоматически. Для русского сообщения используется нейтральная форма `Напоминание из списка «Иван»`, чтобы не произносить ошибочное `для Иван`. Дополнительные русские варианты ответов «да», «нет» и указания владельца зарегистрированы именно в `assist_satellite.ask_question`.

**Ограничение:** интеграция переводит сообщения, созданные самим FGR. Системные сообщения встроенного Assist, сервисов STT/TTS, прошивки Яндекс Станции и других разговорных агентов не входят в FGR — их язык настраивается отдельно. Реальная возможность вести уточняющий диалог зависит от поддержки `START_CONVERSATION` конкретным спутником.

## Обновление существующей тестовой установки

Для исправления английских уточнений **одной замены YAML недостаточно**. Установите из текущей ветки весь каталог `custom_components/fiendishly_reminders`: в нём изменены `intents.py`, `voice_ru.py`, `__init__.py`, `store.py` и `translations/ru.json`. Файл `custom_sentences/ru/reminders.yaml` должен быть из той же ветки. После резервной копии обязательно **перезапустите Home Assistant Core** — `conversation.reload` обновляет фразы, но не Python-код интеграции.

Проверки автоматизированы в GitHub Actions: оригинальный английский тестовый набор, русское сопоставление Hassil, тесты диалогов с тишиной/непонятным ответом и тесты фактического пути `deliver` (голос, телефон, постоянное уведомление). Эти тесты не запускают действия в вашей HAOS и не подменяют реальную голосовую проверку.

## Открытые вопросы

- Сообщения и произносимые подтверждения в основном русифицированы, но расширение языков за пределы русского и английского потребует дальнейшего выделения общего интерфейса локализации.
- Для новых напоминаний язык уведомления сохраняется при создании; старые записи без языка наследуют локаль Home Assistant.
- Сложные границы повторений («до конца месяца», «следующие шесть недель») и ответные реплики на уточнения требуют дополнительных тестов перед обещанием полной функциональности.
- В спорном случае сохранение напоминания следует предпочитать бездоказательной отмене. Проверьте подтверждения на конкретном спутнике.
